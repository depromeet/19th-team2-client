# apps/ut — UT용 페이지 (2026-11-28)

디자인 파트가 만든 UT 프로토타입(`1124최종.html`)에 GA와 단축어 연동을 붙인 정적 페이지다. UT가 끝나면 지운다.
빌드가 없고 pnpm 워크스페이스 패키지도 아니다(`package.json` 없음). Biome은 `**/public`을 검사하지 않는다.

- 주소: https://chi2kawa-ut.vercel.app/
- 배포: Git 연동 없이 이 폴더에서 `npx vercel deploy --prod` (Vercel이 `public/`을 그대로 내보낸다)
- GA4: 속성 'UT 1128'(팀 공용 계정), 측정 ID `G-HEPCQCS2M4`. 맞춤 측정기준·측정항목은 아래 이벤트 파라미터 이름 그대로 등록돼 있다.

## 진행자용 QR 페이지

`/qr.html`을 진행자 폰에서 열어 자리(1~4)·타임(A~F)·기기(참가자 기기/팀 기기)를 고르면 참가자 코드(예: C3)와 QR이 나온다. 참가자는 QR 하나로 시작하고, 알림·시각화 Task는 진행자 숨은 메뉴로 넘긴다. 이 페이지는 GA를 보내지 않는다.

## 설정 (`public/index.html` 스크립트 맨 위)

- `GA_ID`: GA4 측정 ID. 비어 있으면 콘솔에만 찍는다.
- `SHORTCUT_NAME`: 단축어 이름 `chi2kawa-ut`. [불러오기]와 알림 Task가 이 이름으로 단축어를 실행한다. 한글 이름은 기기마다 저장 방식(NFC/NFD)이 달라 못 찾는 일이 있어 영문으로 뒀다. 같은 단축어를 여러 번 받으면 이름 끝에 ` (2)`가 붙어 못 찾으니, 타임 사이에 기존 단축어를 지운다.
- `SHORTCUT_ICLOUD`: 아이폰에서 만든 단축어 iCloud 공유 링크(11/25 연결, 이름 chi2kawa-ut). 링크는 만든 순간의 복사본이라 `make_shortcut.py`로 단축어를 고치면 아이폰에서 링크를 새로 만들어 바꿔야 한다. 비어 있으면 서명한 파일(`public/chi2kawa-ut.shortcut`)을 받는다.
- `EXAMPLE_MINUTES`: 빌려준 기기·단축어 실패·안드로이드일 때 보여 줄 예시 사용 시간(분).

## 진행자 숨은 메뉴

참가자 QR 하나로 끝까지 진행하려고, 어느 화면에서든 오른쪽 위 구석(72px)을 1초 길게 누르면 [단축어 단계로] [오늘 화면으로] [알림 Task로 가기] [알림 눌렀을 때 화면] [시각화 Task로 가기] [처음부터 다시] [QR 페이지 열기] 메뉴가 진행 순서대로 뜬다. 위쪽에 지금 참가자 코드·기기·플랫폼이 보이고, [처음부터 다시]는 두 번 눌러야 실행된다(참가자 코드와 기기 설정은 유지). 투명 버튼을 덮지 않고 누른 위치만 봐서, 그 자리의 알림 배너 같은 요소는 짧게 누르면 그대로 눌린다. 참가자 코드와 팀 기기 여부는 그대로 이어진다.

## 단축어

단축어가 넘긴 오늘의 앱별 사용 시간(`#d=`)에서 인스타그램 시간만 읽어 시급으로 환산해 보여 주고, 주소에서 바로 지운다(# 뒤는 서버와 GA로 가지 않는다). 팀 기기를 빌려준 참가자(`lend=1`)에게는 기기 주인의 기록 대신 예시 값을 보여 준다.

[불러오기]는 `shortcuts://run-shortcut?name=<SHORTCUT_NAME>&input=text&text=<pid>`로 단축어를 실행하고, 단축어는 `?pid=<입력>#d=…`로 페이지를 다시 연다. 단축어는 기본 브라우저로 돌아오므로, 처음 연 브라우저(카톡 안 브라우저 등)와 달라도 참가자 코드가 이어지게 하려는 것이다.

단축어는 하나만 설치한다. 입력(참가자 코드)이 있으면 사용 시간 불러오기, 입력 없이 실행하면 알림 예약(인스타그램 열기 + 2분 뒤 미리 알림)으로 동작한다.

`shortcut/make_shortcut.py`로 만들고 macOS `shortcuts sign`으로 서명한다(사용법은 파일 맨 위).

## 알림 Task에서 가짜 피드를 쓰는 경우

진짜 인스타그램 대신 가짜 피드와 페이지 알림 배너로 진행하는 경우는 셋이다.

1. 빌려준 폰(`lend=1`): 기기 주인의 인스타그램 계정을 보여 주지 않으려고 처음부터 [피드 열기]가 나온다.
2. 안드로이드: 단축어가 없어 처음부터 피드로 간다.
3. 준비 화면의 [인스타그램을 안 써요]를 누를 때.
   [인스타그램 열기]를 누르면 화면은 그대로 두고, 인스타그램을 보다 사파리로 돌아온 순간 08 알림 화면을 띄운다. 사파리의 '단축어에서 열까요?' 확인 창 뒤로 08이 미리 비치지 않게 하려는 것이다. 8초 안에 돌아오거나(확인 창 취소, 인스타그램 없음) 3초가 지나도 앱 전환이 없으면, 자동으로 피드로 넘기지 않고 준비 화면에 [인스타그램을 안 써요]로 피드를 보라는 안내를 띄운다.

## GA 이벤트

디자인 파트 데이터 태그(1124최종.xlsx)의 이벤트 9개를 그대로 보낸다. 거기에 더해 아래를 보낸다.

- 모든 이벤트에 `device`(participant·team, 팀 기기를 빌려줬는지), `platform`(ios·android·other)과 `pid`(같은 기기를 여러 참가자가 이어 써서 사용자 속성과 별도로 붙임)
- `demo_data_use` (`reason` = android·fallback): 단축어 대신 예시 데이터로 넘어갈 때
- `shortcut_complete`의 `data_source` (shortcut·lend·shortcut_unparsed). shortcut_unparsed는 사용 기록 형식을 못 읽어 예시 시간을 보여 준 경우: 실제 기록인지 빌려준 기기의 예시 값인지
- `shortcut_guide_view`: [불러오기]를 눌러 '한 번 허용' 안내 시트가 뜰 때
- `shortcut_run_click`: 안내 시트에서 [확인하고 불러오기]를 눌러 단축어를 열 때. start만 있고 이게 없으면 '단축어 추가'에서, 이게 있고 complete가 없으면 '한 번 허용'에서 막힌 것
- `alert_task_start`: 알림 Task에서 [인스타그램 열기]를 누를 때
- `alert_return` (`away_ms`): 알림을 보고 사파리로 돌아와 08 화면이 보일 때. response_ms는 이때부터 잰다
- `alert_instagram_fail` (`away_ms`): [인스타그램 열기] 뒤 8초 안에 돌아와 인스타그램이 안 열린 것으로 보고 안내를 띄울 때
- `alert_open_slow`: [인스타그램 열기] 뒤 3초가 지나도 앱 전환이 없어 안내를 띄울 때
- `alert_return`의 `reloaded`: 인스타그램을 보는 사이 사파리 탭이 정리돼 다시 열렸을 때(10분 안이면 08로 돌아온다)
- `feed_banner_show` (`nth`, `likes`, `swipes`, `reads`, `scroll_px`, `feed_ms`). swipes는 카드뉴스를 넘긴 횟수, reads는 본문 [더 보기]를 누른 횟수 · `feed_banner_click` (`nth`, `click_ms`) · `feed_banner_timeout` · `feed_banner_swipe`: 빌려준 폰 피드의 알림 배너. 8초 안에 안 누르면 사라지고 30초 뒤 한 번 더 뜬다
- `moderator_menu` (`from`): 진행자 숨은 메뉴를 열 때
- `moderator_reset` (`from`): 진행자 메뉴에서 처음부터 다시를 실행할 때
- `viz_next` (`minutes`): 시각화 Task에서 진행자가 화면을 넘길 때
- `end` 화면의 page_view: 알림 버튼을 누른 뒤의 종료 화면

## GA 기록에서 알아 둘 것

- 시각화 Task(`#viz`)는 screen_name `viz`로 남는다. 시트의 `today`는 단축어를 마친 직후의 오늘 화면만 뜻한다.
- [예시로 이어서 보기]는 `shortcut_complete` 대신 `demo_data_use`만 남긴다. 단축어 완료율을 셀 때 예시로 넘어간 사람은 따로 본다.
- 단축어가 새 탭으로 페이지를 열면 원래 탭은 기록 없이 오늘 화면으로 따라간다(같은 화면이 두 번 집계되지 않게). 그래서 새 탭의 첫 page_view에는 prev_screen이 없다.
- 시트에 없던 화면 `viz`, `alert_prep`, `feed`, `end`와 위 추가 이벤트·매개변수는 맞춤 정의에 모두 등록되어 있다(2026-11-25 확인).
